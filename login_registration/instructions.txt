ANTIGRAVITY PROJECT INSTRUCTIONS
Interactive UI & Frontend Development — TASK 2
Timeline: Days 13–24

PROJECT GOAL
Build a polished, responsive, user-friendly Login and Registration web interface using HTML5, CSS3, JavaScript, and Bootstrap 5. The final result must be mobile-first, visually modern, interactive, and ready to demonstrate in a 3–5 minute video.

IMPORTANT
- Complete the project end-to-end.
- Do not leave placeholder sections, broken links, console errors, or unfinished UI.
- Keep the implementation clean, organized, reusable, and easy to understand.
- Use Bootstrap 5 for layout/components while adding custom CSS for branding and visual polish.
- The project is frontend-focused, but include the requested AJAX/PHP demonstration structure.
- If a PHP/MySQL backend is not required to run the UI, keep backend integration lightweight and clearly separated so the frontend works immediately.

1. BOOTSTRAP 5 MASTERY

Use Bootstrap 5 properly throughout the project.

Required:
- Bootstrap grid system: rows, columns, and responsive breakpoints.
- Responsive Navbar.
- Bootstrap Cards, Modals, Buttons, Forms, Alerts, and utility classes where appropriate.
- Responsive utility classes such as d-none, d-md-block, d-md-none, etc.
- Mobile-first responsive design.
- Avoid unnecessary custom CSS when a Bootstrap utility/component already solves the requirement.

The interface must look correct at:
- Mobile phones
- Tablets
- Laptops
- Desktop screens

2. CUSTOM STYLING

Create a consistent custom design system.

Requirements:
- Define a professional custom color palette for branding.
- Use CSS variables for primary, secondary, accent, background, text, and border colors.
- Add smooth hover effects to buttons, links, cards, navbar items, and interactive elements.
- Add subtle transitions and animations without making the UI distracting.
- Use Google Fonts and suitable icons (preferably Bootstrap Icons).
- Maintain good spacing, typography, contrast, alignment, and accessibility.
- Do not use excessive gradients, animations, or visual clutter.

Suggested visual direction:
- Modern professional SaaS/portfolio-style authentication interface.
- Clean white/light surfaces with a strong teal/blue brand accent.
- Rounded cards, subtle shadows, smooth transitions.
- Login and registration pages should feel like part of the same product.

3. FORM HANDLING WITH JAVASCRIPT

Implement client-side validation for both Login and Registration forms.

LOGIN FORM
Include:
- Email/username field.
- Password field.
- Show/Hide Password control.
- Required-field validation.
- Valid email format validation if email is used.
- Clear inline validation/error messages.
- Prevent submission when validation fails.
- Show a success state when valid.

REGISTRATION FORM
Include:
- Full name.
- Email.
- Password.
- Confirm password.
- Show/Hide password controls.
- Required-field validation.
- Email format validation.
- Password strength validation.
- Password and confirm-password match validation.
- Clear inline validation/error messages.
- Prevent submission when invalid.
- Show a success state when valid.

UX REQUIREMENTS
- Do not rely only on browser default validation messages.
- Use JavaScript to provide friendly validation feedback.
- Validation should happen on submit and, where useful, while the user is entering data.
- Password visibility buttons must work correctly.
- Avoid page reloads for validation-only interactions.

4. AJAX BASICS

Demonstrate AJAX/fetch functionality.

Required example:
- Use JavaScript fetch/AJAX to send data to a PHP endpoint without reloading the page.
- Create a simple PHP endpoint such as check-user.php or api/check-user.php.
- The endpoint can use dummy/mock logic if a database is not necessary.
- Demonstrate checking whether a username/email already exists.
- Display the result dynamically in the registration form.

Example flow:
1. User enters an email.
2. JavaScript sends the email to the PHP endpoint using fetch().
3. PHP returns JSON.
4. JavaScript displays an available/already-registered message.
5. The page does not reload.

Handle:
- Loading state.
- Successful response.
- Existing user response.
- Network/server error.
- Invalid input.

If PHP execution is unavailable in the preview environment, keep the frontend functional and provide a clearly documented fallback/mock response while preserving the real PHP endpoint for deployment.

Create the following pages/components:

PAGES
- index.html or a suitable landing/authentication entry page.
- login.html.
- register.html.

If a single-page authentication flow is more appropriate, it is acceptable to combine login and registration into one polished page, but separate pages are preferred for demonstrating navigation.

REUSABLE COMPONENTS
- Responsive Navbar.
- Footer.
- Authentication card/container.
- Reusable form styling.
- Reusable buttons.
- Alerts/validation messages.
- Modal if useful.

NAVIGATION
- Navbar links must work.
- Login page must link to Registration.
- Registration page must link to Login.
- Logo/brand must return to the main page.
- Footer links must not be broken.

6. RESPONSIVE UI REQUIREMENTS

Use a mobile-first approach.

Check:
- No horizontal scrolling.
- Images never overflow their containers.
- Text wraps correctly.
- Forms remain usable on small screens.
- Buttons are easy to tap.
- Navbar collapses correctly on mobile.
- Authentication card adapts to different screen sizes.
- Desktop layout uses available space without becoming excessively wide.

Use responsive images with:
- img-fluid
- object-fit where appropriate
- sensible max-width/max-height rules

7. ACCESSIBILITY

Include:
- Proper labels for every form input.
- Meaningful button text.
- Keyboard-accessible controls.
- Visible focus states.
- Adequate color contrast.
- aria-label/aria-describedby where useful.
- Semantic HTML5 elements.
- Do not use icons alone when their purpose is unclear.

Ensure all images, icons, fonts, and other assets load correctly.
